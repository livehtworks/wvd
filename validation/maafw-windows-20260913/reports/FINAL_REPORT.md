## 关键结果

| 项目 | 实测 |
|---|---|
| 停止 | 识别等待、协作回调、嵌套子流程及 clone 子流程都退出；未继续发输入 |
| 异常 | 回调内受控 C++ 异常被捕获转为失败；进程未崩溃 |
| 点击失败 | 假控制器返回失败后没有进入业务 Completed |
| 恢复 | 子流程报告 RecoveryRequired，旧根退出/释放后新会话启动；拒绝旧 generation 目标 |
| Context | clone 的 override 不污染父 Context；共享停止；后续新会话使用原始配置 |
| 历史 | 一次有限任务的 1000 个节点均可由公共 API 查询，不能据此断言历史有上限 |
| 两包隔离 | 两个同时存活的 Resource/Tasker，用同名 SameNode 和不同内容的 target.png，分别命中不同坐标 |
| WVD 基础图像 | 王城 Inn 正例通过；启动免责声明、标题页两个真实负例均拒绝 |
| 坐标 | 900×1600 和派生 1080×1920，经框架控制器只缩放一次，最终假设备坐标误差不超过 1px |
| 异比例 | 1080×2400 派生图被明确拒绝，输入次数 0 |
| OCR | 固定英文 ppocr_v3 轻量模型，原生输出 Pause，分数约 0.9997 |
| 中文路径 | 原生程序、模型、输入图片、模板与输出目录包含中文和空格，修正探针编码后通过 |
| 系统截图 | ADB Encode 正式 50/50 有效，另计 5 次预热 |
| WVD 截图 | ADB Encode 正式 50/50 有效，另计 5 次预热；该组是游戏启动资源确认画面 |
| MuMu 增强截图 | 单独指定 EmulatorExtras，5 次预热 + 5 次正式采样全部成功；王城图像方向、颜色正确 |
| 系统点击 | 原生点击设置的应用导航入口，画面变化符合预期，再点击返回原导航页；未改开关 |
| 清理与隔离 | 466 个生产相关文件哈希未变，Git 干净，没有残留探针进程 |

停止的框架原始状态实测可能是 Invalid(0)，不是业务 Completed。
源代码的停止操作会清空 AsyncRunner 状态表，因此适配层必须另外保存业务终态，并记录两种结果。
此行为是本轮发现的集成注意项，不据此判断停止失效。

## 必选失败：P4-LIFETIME

原始证据：`runs/P4-LIFETIME-c328fe0a/`。

同一进程内，5 轮预热、30 轮正式会话，每轮 100 个有限节点。
每轮完整销毁 Tasker → Controller → Resource，之后静置 250 ms 采样。

| 指标 | 结果 | 门槛 |
|---|---:|---:|
| 最后 10 轮与最初 10 轮 Private Bytes 中位差 | 5,814,272 B，约 5.55 MiB | ≤32 MiB，通过 |
| Private Bytes 线性斜率 | 273,496 B/轮，约 267.09 KiB/轮 | ≤256 KiB/轮，**失败** |
| Handle 中位差 | 0 | ≤8，通过 |
| Thread 中位差 | 2 | ≤2，通过 |
| 自有 Session 存活数 | 每轮 0 | 0，通过 |

后段增长伴随线程数由 5 到 7，但这只是相关现象。尚不能判定来自 Maa 历史容器泄漏、系统线程池、日志缓存或分配器保留。
未修改门槛、延长预热以美化结果、循环重跑直到出现 PASS，也未修改 Maa 核心。
下一步应针对这一个最小复现定位存活分配/线程来源，再做一次有明确修改原因的完整复测；不应马上迁移 WVD。

## 已修正的探针问题

1. **中文路径**：第一次原生启动发生多字节转换异常。加入进程级 UTF-8 manifest，补齐 SDK 插件目录后，回调、OCR、模板三条实际链都通过。无系统区域设置修改。保留第一次 stdout/stderr。
2. **冷启动等待**：管理器报告 Android started 时，ADB 还可能不可用。改为在既定有界轮询内继续验证连接和 `sys.boot_completed=1`。第二次正常关开完整验证了该修正，没有杀死共享 ADB 服务。
3. **系统方向**：系统/Clash 是 1600×900，WVD 是 900×1600。最初用 WVD 尺寸约束检查 Clash 导致一次尺寸失败。后续按已观测的实际场景分别校验，并保存可解码但尺寸不符的帧。未改模拟器显示设置。
4. **C++ 图像指针类型**：编译阶段将公开的 opaque raw-data 指针误作有元素类型指针；已显式转换为字节指针。失败编译日志保留，未改 SDK。
5. 假设备协作停止检查点使用互斥锁配合条件变量，避免丢失唤醒；最终停止相关用例再次通过。

这些是验证工程的修正，不是 WVD 的修复。并非每个中间成功运行都对应最后一版探针源码；最终产物哈希另列，原始失败证据不删除。
生命周期失败发生在加入 Unicode manifest、实机启动辅助前；这些后续改动没有针对内存失败作修复，因此该项保持 FAIL。

## 未验证与明确限制

- **P1-NEXT / P1-PAUSE：UNVERIFIED。** 本轮没有通过来源核实的完整真实正负样本集，不为取得样本主动进入危险战斗。当前发行目录与仓库测试中未找到可用的相关历史截图。
- 原 `_check` 和 `_check_bright_mask` 通过 AST 从固定文件提取；基础对照使用未修改的 `_check`，只替换无副作用诊断依赖。单有效 ROI 和无 ROI 已测，多 ROI / 非法 ROI 的历史行为未测。
- C++ 基础适配器通过 CustomRecognition 调用原生 TemplateMatch 的 TM_CCOEFF_NORMED，再输出 WVD 的模板中心。没有宣称已经承接亮色遮罩、多尺度 NEXT、Pause 布局和反证全部语义。
- 原 WVD 的可选 pytesseract 模块和系统 tesseract 不可用，未安装全局依赖。原 Pause 仍有布局分支；本轮合成 OCR 不替代该分支回归。
- 图像标签来自 `codex_visual_review` 或合成埋点，不是人工金标准。
- 1080×1920、1080×2400 仅为离线派生图片，不是实际改动设备分辨率后的验证。
- 未验证蝎女完整悬赏链、连续挂机、其他设备、多机抢占、断网/坏 DLL 等所有错误组合。
- 实机恢复验证是独立探针重建 Controller/Tasker，不是把 Maa 接进现有生产状态机。
- Spark/Linux ARM64 只做静态审查，见 [PORTABILITY_REVIEW.md](PORTABILITY_REVIEW.md)。
