## 保留规则

| 材料 | 长期保留内容 | 收尾方式 |
| --- | --- | --- |
| 当前架构、合同、数据职责、状态 | 当前有效事实及未结事项 | 原页更新；不复制整份旧状态 |
| 已完成工作包、验收报告 | 主题摘要、适用版本、必要限制和 Git 定位 | 原文进入 Git 后从当前树移除；不再本地复制归档 |
| 当前回归测试输入 | 真实用例引用的最小素材及来源 | 与测试同步维护；不为每次运行再留一套 |
| 隔离运行复制的图片/模型 | 原回执、失败原因、独有复现输入 | 可证明相同且可重建的副本收尾；失败不等于整棵夹具永久保留 |
| 运行截图、调试日志 | 未解决问题的必要身份/时间段/原帧 | 正常轮转场不额外复制；问题结清后归纳，避免每次巡检抓图 |
| 正式结果、未决输入、用户修改 | 原业务权威与恢复依据 | 不适用普通资料清理 |
| 当前/已核回滚 EXE/PDB、设备备份 | 当前实际恢复所需的匹配集合 | 退出引用后按明确清单处置，不按每轮增加整套 |

同一问题共用一个记录和证据入口；新的不同失败只补必要差异。没有具体像素疑点不截图或看图，不按日期删除未知材料。普通trash只接收已退出引用的废弃或可重建材料；仍承担正式恢复职责的原件不能依赖普通trash长期保存。永久删除由用户明确决定，不能因路径含trash就由代理推断可删。本轮用户已确认清空trash，旧迁移清单中的目标不能再默认可恢复。
