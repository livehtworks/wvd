- 每轮memory-lifecycle.json中的heap_summary_before/after最多64条逐堆地址、主堆标记、实际分配/内部提交/保留量、错误及统计耗时；失败字节为null，原四个固定槽不扩展为无限历史。关闭日志则不做昂贵HeapSummary，堆维护保留。

## 分析与异常判定

本轮扩展现有analyze_memory_owners，不增加平行诊断服务：先核PID/创建时间/协调器和轮次顺序，再比较同heap_resources_optimized边界。逐堆部分额外核查唯一地址、主堆、成功状态及分项与总量相等；出现/消失的堆单列、缺失侧不补0。同地址可能复用，不包装成分配栈归因。

后续在已完成第1、10、20、30轮及异常停止处，分别比较实际堆分配、堆内部提交、进程私有提交、对象live和统计耗时。阶段缺失、写入/截图失败或丢弃应单列采集异常，不静默跳过。进程变化必须分组，不能拼接为一条增长趋势；中间轮没有batch_payloads_released属于批次仍持有请求，不补为0。

- 实际allocated与对象live同时增长：继续追对应所有者/初始化销毁配对。
- allocated趋稳、内部commit和私有提交增长：按具体堆地址确认滞留，不能直接宣称泄漏或缓存无害。
- 进程增长但已测堆不增长：记录覆盖边界，下一次有界取证转非堆/外部运行库来源；不简单相减伪造所有权。
- 同时记录系统提交压力及已有其它进程占用证据；不把整机压力等同本工具独占，不结束其它模拟器。

比较工具只读正式目录，派生报告必须写到data外独立目录；原始截图/转储可能含用户资料，不随源码推送。

新增分析器仅做四项针对性验证：变化和耗时保留、消失/新增不补0、缺字段/失败/重复地址/总量不一致拒绝、输入不被修改；已通过。另读取前轮真实生产协调器停止验收的5堆记录，调用同一分析函数成功核对。不是新游戏测试，也不声称完成任何本批轮次。
