## 新发现与待定位

### 两轮反复切换单角色自动战斗

第2轮耗时302.594秒，第19轮280.303秒；战斗分别74.728、65.557秒，而第35、36轮战斗约14秒。两轮各经过13次Prepare、10次NoSelection、10次CharAuto_Enable及10次DisableCharAuto；均有一次宝箱，但不能据此认定宝箱导致慢战斗。

`next/native/games/wvd/combat/turn.cpp`中NoSelection进入单角色自动战斗；`auto_combat.cpp`以自动按钮已开启确认Enable，随后DisableCharAuto在战斗菜单仍在且按钮开启时关闭。该分支没有明确等待行动者变化或攻击完成。旧 `src/script.py` 的AutoThisChar在开关间等待0.5秒，关闭后等待2秒。

这构成“可能过早关闭自动战斗”的源码风险，但现有事件尾窗不足以证明10次都是同一角色空转，而不是多次有效行动。后续应记录行动者、选择失败原因及前后行动进展，再以行动进展确认收敛；本次不直接加固定等待或修改策略。

### 事件历史并不完整

36份result的 `events.resync_required` 均为true。`next/native/app/application.cpp`配置事件环容量1024；`next/native/storage/run_store.cpp`的EventJournal在达到容量后淘汰早期非关键事件，终态保存剩余窗口。动作耗时文件独立保存，不因此丢失上述计时与输入记录，但不能还原完整的早期角色选择及恢复事件。

`diagnostics.complete=true`和分析器 `faults=[]`不能解释为完整事件历史无异常。建议保留UI有界环，同时将必要的角色选择、生命周期和恢复事件限额滚动落盘，不靠无限放大内存环解决。
