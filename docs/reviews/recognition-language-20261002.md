# 识别语言隔离

## 问题与范围

用户当前使用繁中界面，英文版与繁中版不会同时存在。既有工作台已有语言选择，但部分原生探针和显式包含两套素材的复合条件仍会扫描英文模板；王城剧情排除条件还会间接匹配14个英文对话选项。

本次仅处理识别语言选择与无效模板匹配，不修改ROI、置信阈值、输入重试或10秒跳轮等待，不将未知模板强行视作英文，也不删除旧任务能力。

## 实现

- 复用工作台`resourceLocale`，显示名称改为“游戏识别语言”；繁中默认值、既有持久化与运行中锁定沿用原实现。不增加第二套配置权威。
- 原生处理器使用运行冻结的`resource_locale`，从构建时冻结的语义目录生成模板语言索引。语言不从文件名推断，`template_languages`可显式声明文字模板或跨语言共用内容。
- 对不属于当前语言的已分类模板，在加载/解码/匹配之前返回带`template_language_excluded`原因的NoHit。它不是实际像素匹配失败，不生成虚假置信分数或点击坐标；当前语言缺图仍报Error。
- 此处跳过的是模板识别路径；发布快照仍按既有清单校验并持有资源原始字节，本次没有裁掉语言包成员，不宣称已消除全部素材常驻内存。
- `Stay`与`Stay.png`按同一模板处理；同帧缓存键原本就含语言，不跨语言复用识别结果。
- 繁中不运行只有英文素材的`default_dialogue`扫描。特殊对话仍走其独立处理链，不把未实现的繁中选项识别宣称为已实现。
- NEXT、Pause、Active、Auto、Spd在繁中界面仍可能是英文；角色头像、纯图标与数字跨语言共用。逐图确认`retry_blank`没有文字，不能随英文retry一起禁用。
- CMake从唯一语义目录嵌入全部资源语言信息，仍使用分段字符串避免MSVC字面量上限；不在每次识别时读文件或重新建立索引。

- 前端只改标签并同步已有控件断言，沿用原语言选择、状态锁和启动接口。
