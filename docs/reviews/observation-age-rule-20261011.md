# 100毫秒截图作废规则核查

## 来源与错误

仓库提交`4c466e14fa514fa177380e902afe373c8f20c3b2`，提交作者`Codex <codex@local>`，`next/native/runtime/flow_executor.cpp`的`FlowExecutor::tick()`中已有这条项目自定义规则，没有行业标准来源：距取图完成达到100ms，在下一次执行时调用`invalidate_observation()`，清除截图和已选识别结果。

它不是在第101ms中断识别函数，而是会在函数返回后的下一次执行中丢弃仍待使用的结果。因此慢识别可能被重复执行。原注释的目的为防止正向观察或子流程返回组成只读循环，但用识别耗时决定结果有效性是错误做法。

## 当前源码候选

- 撤除按100ms作废的分支，不以更大的固定数字替换。
- 同一张仍有效的截图、同一识别请求，选中后直接使用结果；输入场景和目标同样交给后续执行使用。
- 设备、连接、输入状态对应的截图身份失效时，撤销旧截图及其结果。等待、输入和再次返回同一选路点仍重新观察，不允许只读循环永远使用旧图。
- 编译转换仅去掉与输入场景内容完全相同的额外判断，不移除不同条件或原输入保护。

这些均为本项目修法。没有把它们宣称为行业规定，也没有扩大ROI、降低阈值或放宽未确认输入保护。
