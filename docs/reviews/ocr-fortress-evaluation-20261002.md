# 要塞郊外繁中OCR小样本试识别

## 范围

用户授权“先试一下检测”。只读2026-10-02手动采集的4张原图，不连接或输入设备、不修改正式模型或Service、不部署、不启动循环。

复用已编译生产`wvd::recognition::OcrEngine`及项目内RapidOCR/OcrLite、OpenCV 4.12、ONNX Runtime 1.22.1。隔离目录`next/.local/ocr-fortress-20261002/`保存独立CMake探针、模型、plan.json、运行日志。检测模型沿用当前det.onnx，仅比较PP-OCRv5 mobile/server识别模型；这不是完整PP-OCRv5检测管线，也不代表正式Service已支持繁中。CPU为Ryzen 7 5800X，引擎沿用2线程设置，不使用GPU。

4张原图来自`next/.local/material-collection/fortress-20261002/session-20261002-221351/`：

- 第55帧：清晰楼层列表。
- 第54帧：第十区文字上有触控圆圈。
- 第46帧：不落的要塞入口、回到城镇。
- 第53帧：列表淡入过渡。

列表ROI为`[400,150,480,900]`，入口ROI为`[400,800,480,250]`；原始BGR裁切，不缩放、锐化、二值化或指定每行答案。每张图连续识别2次，每模型8次，共16次，不将重复识别称为独立样本。

### 具体差错

- mobile将第6、7区“史前迴廊”读作“史前迪廊”，置信分约0.93～0.94。
- mobile在无触控圈第55帧把“領”输出成简体“领”；在第54帧漏掉“3F”的F，输出“第十區-要塞3領主室”，置信分仍约0.99。
- server在这两帧的8个区域都读对，包括“迴廊”“3F領主室”。
- 淡入帧server只读出不完整“第六”，置信分约0.85；能认到“返回”不证明目标列表已加载完成。
- ROI顶部包含被截断的英文副标题，两个模型都输出了副标题片段；这是无关检测结果，应由完整业务目标规则排除，不算楼层名称。

## 结论与接入边界

这批数据支持继续评估server模型用于菜单名称确认，但不支持立即全面替换模板。推荐按需识别列表，结合区域序号、地点名、楼层与候选唯一性；单靠高置信分或“要塞”两个字不可点击。内容淡入、字段缺失或候选冲突时重新观察，不猜目标、不因为一次OCR失败重启游戏。

全列表server约0.8～0.94秒，不宜每帧重复执行。后续若选择接入，可在页面变化后读一次，或模板定位含糊时核对对应文字；单行ROI的实际耗时本轮未测，不能从入口两行数字直接宣称单行速度。城市独有背景、通用图标继续使用模板。

正式Service目前仍拒绝非ASCII目标，发布包仍锁定英文模型。此次直接调用同一底层OcrEngine试模型，没有绕过正式输入门禁、没有放开运行入口。真正接入还需明确模型/字典锁定、繁中文本匹配契约、语言配置和目标选择规则；不能只移除ASCII检查。
