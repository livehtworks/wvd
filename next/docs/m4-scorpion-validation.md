# M4 蝎女与六手悬赏

固定旧源码4074/4155两个case，由 `tasks/bounty_cycle` 编译，
`quests::BountyCycle`归属WvdRunState且仅存阶段/回执。普通蝎女一轮3个Session，
加六手一轮4个Session：准备、各自路线并返城、交付住宿。正常续段仍由RunCoordinator管理。

## 保留语义

- BeautifulOre优先于Triumph；否则GhostsOfYore。BeautifulOre跳跃后不增加王城传送，
  另外两种入口返回要塞再进入王城。源码这些调用没有传CSC_symbol，默认None，
  因此使用无因果子图不是忽略ACTIVE_CSC；LBC/COS的显式因果调整仍未实现。
- 蝎女B2FTemple两点505/760、506/821；六手另进B5FWarpedOnesNest两点454/662、135/714。
  不能提前离本就算两点完成，每条路线后重新找公会。
- 加六手需要两次已确认交付，每次退出菜单，再找下一份，不连续点旧坐标。
  交付摘要保留已完成份数，恢复不会补发已有回执；待确认交付则停止自动恢复。
- 开始计数不同于完成数。住宿使用 `(开始次数-1) % (REST_INTERVEL+1)`，
  不受ACTIVE_REST控制；需要住宿时必须取得本周期真实付款回执。
- 跳跃/跨城转场前记录意图；新帧终点未确认时不通过重启盲目重放。
  DHI分支本来不传送，单独记录跳过阶段，不伪造传送输入或待确认消费。

## 城市间传送

确认大地图后才进入既有世界地图定位子图。仅看见起点Inn不能Completed。
这不更改既有从地下城回城的travel_world语义，也不开放真实设备测试。
