# M4 住宿付款确认窗口

## 问题与修正

原有已住宿回执能防止回执写入之后重付，但没有覆盖“付款点击前后到回执提交之间”
的中断。普通导航只见城市时可能重新走住宿，无法从城市场景判断之前有没有付款。

在使用 WvdRunState 的完整住宿链中，新增 `inn_payment_prepared`：当前确认页上、
可能消费的 OK 输入之前记录 `inn_payment_pending`。付款后新帧确认 Stay 且 OK 消失，
才允许 `inn_rest_completed` 清待定、增次数。未准备的完成事件拒绝，不倒推意图。

意图跨代次保留；已确认回执保持原 supply_cycle 幂等边界。待定状态下，旅店重入和
回城准备返回 `departure.inn_payment_unconfirmed`，生命周期策略拒绝恢复重放，
入本也不能用重置周期丢弃待定事实。它不是支付事务的精确一次保证：没有游戏侧事务号，
不能自动分辨“没有发出”与“发出但确认丢失”，因此保留待人工核对，而不是猜测重付。

独立无状态的 UI 子图仍不提供跨段回执保证；完整任务必须使用 record_completion=true。
没有修改旧旅店代码、账户资源或用户配置，也没有导入历史待定记录自动续跑。

## 验收状态

实现与测试已写，尚待构建和执行，不算通过：

- 原住宿、皇家房间退路、强制住宿、已付退出失败与不重付测试继续保留。
- 状态测试拒绝无准备结算、重复准备幂等、已确认清意图、恢复后待定不计数/不丢失。
- 正式离线付款第四次输入停止或拒绝，保留意图且次数为零，恢复端口输入为零。
- 付款后未知页保留失败和待定，绝不重付。

本项修正只能证明同 Run 的保守对账，不能把它说成跨进程自动恢复、真实住宿完成，
也不能代替其它购买/任务交付副作用的逐项验收。
