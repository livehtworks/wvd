# M4 连续住宿

固定旧 `QuestFarm/lovesleep` 的目标为9999次完整住宿。新版不改运行器256段上限，
由 `tasks::configure_sleep_units` 冻结250个正常业务段，每段最多40次，末段39次。
执行仍由RunCoordinator和Maa负责，没有新增线程、执行器或持久化续跑入口。

## 实现边界

- `quests::SleepVisits`仅保存正在进行的住宿及完成次数；`tasks::sleep_visits`
  编译有限图，复用正式的付款、退出旅店链。每批1600秒总预算仍可使异常慢批次失败，
  不代表每次等待都能占满旅店子图的60秒，更不是9999次总运行时间。
- 每次开始新补给周期，不复用上一轮已住宿标志。付款前意图跨恢复保留；
  付款确认计入inn_rests，但必须退出回城后才计入completed_visits，两者不同。
- 同一批次恢复保留去重回执。正常换批只在旧批已经完成、无付款待确认且下一批编号正确时，
  释放旧批的四类住宿签名；其它业务回执、累计次数和事件结果均保留。
  旧代次回调仍被拒绝，不通过清空全部状态解决4096签名容量问题。
- 只读CLI列出lovesleep和所需250段。单批离线运行Completed不等于9999次任务Completed，
  结果内sleep.completed必须另行检查。
