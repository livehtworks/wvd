# M4 单角色战斗动作验证

## 实现范围

`combat/turn.cpp` 将一个角色的动作编译成有限 Maa 图。顺序由 Maa 推进；选定与确认两类有限业务操作只负责新帧选定策略和新帧确认消费，不在 C++ 另写战斗循环。

- 同帧实际头像匹配按原行顺序和最高分选择，包含存在的 `_sp`、`_alt` 资源；0.80 阈值不变。
- 选择仅存 Run/代次/策略 epoch/行和头像名称，不存帧或坐标；段边界、任务点和重置事件清除未完成选择。
- 倍速、最多三次打开详情、等级选择/缺失回落、指定友方目标及 OK 确认均有独立图节点。
- 敌方按 NEXT 0.86、三角 0.86、限定 NEXT 0.60 顺序；每个偏移点重新截图、确认原角色和详情，坐标裁剪到 x=1..898、y=260..900。详情消失后不继续点下一角色。
- 低置信通用识别仍禁止直接授权。专用 `skill_target` 必须有本 Run 已选条目、原角色、详情，以及不存在 OK/友方选择的同帧证据才产生可动作结果。
- 目标失败先关详情再临时开启 Auto，确认开启后关闭并确认关闭；只有该流程确认成功才消费已选条目。角色未匹配不消费。全自动策略走已有持续 Auto 子流程。
- 高等级资源不足只允许一次一级重试；一级仍不足明确请求恢复。防御的第二次点击也重新确认角色，角色变化或战斗结束后才确认消费。

## 语义与未完成边界

固定旧 `StateCombat` 中已选技能的自动兜底返回 True，调用者随后消费行。此前状态报告笼统写“自动兜底不消费”不准确，本轮改为 `AutoFallback` 与 `AutoFallbackConfirmed`，保留失败/取消原测试并增加确认后的测试。

旧资源不足会递归重试，本轮有界一级重试防止无限调用；旧目标批量点击改为逐点新帧确认，符合工作包要求。真实设备、死亡/Pause 恢复、外层整场战斗和完整任务没有因此通过。完整任务分母仍为 58，通过数仍为 0；提交后继续工作包。
