# M4 首次连接失败恢复

## 调用边界

`MaaGateway::initialize` 的控制器连接失败发生在根任务发布前。原来它只产生 Failed，因此即便 Run 绑定了 WVD 恢复策略，协调器也不会进入该策略。

现在用统一的 `connection_failed_before_task` 判定：Failed、精确连接失败码、真实静止、根任务 ID 为零、尝试/接受/底层输入计数均为零。只有显式绑定恢复策略的 Run 才暂缓将此失败写成 Run 的不可恢复终态；Session 原始失败仍保留在逐代次记录中。策略拒绝或预算耗尽不会被改成成功。

恢复仍由原来的 RunCoordinator、新代次、LifecycleRecovery 边界和类型化端口执行。第一轮应用恢复前置不成立则有限升级为重连；实例未运行时再升级实例启动。VPN 必须确认就绪，游戏必须启动且前台正确，随后处理标题/公告/下载，最后继续原任务。启动完成不等于业务完成。

回调异常、资源错误、已启动任务的失败、已经发生输入的失败不具备此资格。没有端口或目标授权仍拒绝。停止与原生对象所有权契约不变，不新增设备直连入口、脚本命令或生产自动回退。

## 验证

### 初始VPN与冻结配置

`007a7d6`在原Lifecycle执行器中增加首段唯一的EnsureVpn许可，不允许首段混入
StopApplication/StartApplication/RestartInstance，也不允许正常续段携带生命周期计划。
配置只在已明确授权的离线目标内选择是否启用VPN；关闭不调用，已就绪则跳过，
未就绪先完成检查，失败走原恢复链。VPN成功不形成业务终态，也不放宽后续帧身份校验。
`AUTO_START_CLASH`、`MAX_CRASH_LIMIT`与状态工厂冻结profile同源，不读取后续编辑值。

本地`m4-workflow-j4if2ou9`、`m4-007a7d6-vpn-handoff.log`中6方法全部通过：
首段/续段/真实设备权限负例、开关与就绪/正常续段、VPN失败恢复和任务拒绝、
过期业务帧拒绝、恢复时冻结开关、崩溃阈值触发实例重启。所有生命周期调用均为离线后端。
另一个状态负例发现uint64最大值未被正确拒绝，正在显式unsigned范围检查后复验；
不得据上述正常阈值通过掩盖该负例。旧验证记录保持其原产物范围。

### 历史恢复验证

七目标构建通过。补充计数后的原生验证 6 方法/7 场景全部通过（33.952 秒，`m4-cold-start-counts-workflow.log`，`m4-workflow-k_63l4m9`）：离线/实例关闭后续接完整住宿链、无恢复策略、回调异常、无生命周期权限、实例启动中停止，以及三次恢复预算耗尽。所有设备状态为隔离测试后端；未查询或连接真实 MuMu。

初始实现检查点 `ce79f95`。复验 EXE SHA256 为 `09622c137c989e0da2ee654d6b9bb5bcfaf4b0f60bf06e2e40a225d7e176b4c4`；离线/关闭成功例的最终代次分别为 3/4，前代次输入为零，最后一代各 8 次，原任务完成而非仅启动完成。不据此宣布 M4.6 全部完成。

计数修正检查点 `d1e624f`。同产物恢复全组 17 方法全部通过（224.472 秒，`m4-cold-start-full-recovery.log`，`m4-workflow-5hv5zq16`），包括迟到返回所有权、错误身份、重试升级和再次故障。M2 核心 102 方法回归通过（91.482 秒，`m4-cold-start-m2.log`）；M3 定点 11 方法回归通过（51.577 秒，`m4-cold-start-m3.log`），未运行 metadata 或固定成本窗口。450 个旧版保护文件重新核对均未改变。

同产物状态组 16 方法通过（4.896 秒，`m4-cold-start-state.log`）。以上不包含后续沙人/祝福提示改动。

首轮 6 方法中 5 项通过、1 项断言失败（17.197 秒，`m4-cold-start-workflow.log`，`m4-workflow-l3h0jrni`）。离线设备重连后原任务已 Completed、8 次输入；失败原因是测试错误地要求有界事件窗口保留全部 8 条输入事件，实际只剩 5 条。没有扩大日志窗口。改为在每次 Session 收集时持久保存逐代次输入计数，核对前代次为零、最终代次为八和总计相等；保留窗口内输入的代次断言。实例关闭子例因前一断言失败未执行，尚不计通过。
