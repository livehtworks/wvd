# M4 有限遭遇战与重复确认

## 实现

- `combat/encounter.cpp` 组合已经实现的单角色图，按显式 `max_turns` 展开有限角色动作。每个角色有独立的详情打开/目标点击预算，不把所有节点的 max_hit 一概放大。超出 1..16 回合参数、4096 节点或 Session 时限时拒绝/请求恢复，不冒充战斗结束。
- 只有回到已确认地下城才结算战斗计数；战斗转宝箱保留 pending/timer，复活页走命名恢复出口。单个角色动作完成不触发整场终点。
- `confirmation_id` 以 Run、业务段、操作和遭遇序号组成。重复观察同一遭遇、重复 resume 和旧收据重放不重复消费；同一节点第二次真实遭遇不再被第一个操作 ID 吞掉。代次/帧号仍作真实性校验，不作幂等键。
- `enable_auto` 增加“已经退出战斗”的独立出口。单独调用仍不能报 Auto 已开启；父战斗图明确绑定这个正常转场。关详情期间战斗结束时，不再点击 Auto，也不消费未确认的兜底条目。

## 验证

首轮 `m4-encounter-tests.log` 的 5 方法通过。新增边界和既有回归整组 `m4-encounter-final-tests.log` 为 25 方法、36 原生场景通过，证据在 `next/.local/m4-workflow-o40ytqdc/`；`m4-encounter-state-tests.log` 的 10 个状态方法通过。每例保存 EXE 和固定 SDK 身份及原始事件。

新增核心断言包括：两个角色依次开技能/选目标；战斗尚未结束但角色预算耗尽；底层拒绝；战斗转宝箱；关详情时战斗已结束；Auto 开关未确认但外层已返回地下城；同一普通插入节点两次遭遇分别计数。合成图只验证因果和控制流，不能证明真实目标质量。
