# M4 未知画面窗口

## 实现边界

固定旧 `GameFrozenCheck` 使用十帧、九次相邻灰度差均值之和，阈值0.15，每十次计算一次。
`vision/unknown_window.*` 独立承接这一数学口径，仅保存一张灰度图与九个差值，不保存十张BGR。
一秒内的重复观察不累积样本，避免高速截图将短暂动画间隙凑成十帧；窗口不再使用跨调用者
共享的全局计数。无效图像、倒退时钟直接报错，不折算为静止。

`unknown_frozen` 在每次观察前按既有就绪/阻塞/面板分类复核。已知页面会清空窗口；结果不带
输入资格。缓存属于一个Gateway，关闭或换代次自然清除，业务状态不存图像或设备句柄。

地下城路线的入口/分派首先观察窗口，只有未识别候选才进入有限的一秒等待，不在未知页面
盲点返回或1/1。十帧静止返回 `dungeon.unknown_static_window`，由原RunCoordinator在真正
静止后决定下一代次恢复。未附恢复策略时保留Interrupted，不自行连接或重启设备。

这只是“持续未知且低变化”的恢复依据，不证明游戏物理引擎死亡；AutoMove/Pause的点击后
无响应检测继续独立存在。400秒遭遇超时、MAX_TRY_LIMIT完整语义、cursedWheel的7300秒
等待/任务转交仍未完成，不用本项替代这些验收。

- 纯窗口与独立灰度参考逐样本比较、静止/运动、快速重复、清空和错误输入。
- 正式Maa地下城入口在未知页产生恢复请求，零游戏输入。
- 新代次应用恢复后回到已到达地图位置，确认任务点；旧段静止证据保留。
- 已知旅店静止页不触发未知冻结。

## 未知重试上限接线

`unknown_exhausted` 使用同一会话窗口的真实未知样本数，消费冻结profile中的MAX_TRY_LIMIT。
保持旧零起点比较边界：上限N的前N个样本不因次数触发，下一样本触发；已知场景优先并清空。
每秒最多计一个样本，不让高速截图导致瞬间耗尽；十帧低变化仍有独立原因，计数不影响差值数学。
地下城/暗灯只在已知分支都未处理时检查上限，产生 `dungeon.unknown_try_limit`，不盲点返回。
当前新增上限0/2和已知旅店的流程负例，待构建；这尚不替代旧全部查找辅助函数的重试参数迁移。

`unknown_exhausted` 仅复核当前未知页面并读取latest计数；增加只读访问不得推进的原生断言。
