# M4 副作用确认窗口

## 问题与处理

普通弹窗中断和业务结果不确定是不同情形。打开菜单后遇 Retry 可以重新观察菜单；目标、恢复或拆陷阱已经点击后遇 Retry，则可能已经产生效果，不能清弹窗后从旧步骤重来。

`PipelineCompiler::stop_if_interrupted_after` 为明确标记的受控动作生成独立的“结果未确认”后继。它保留正常后置条件与实际输入链；覆盖层出现时终止本段，不进入正常 BlockedExit。技能消费、宝箱计数和恢复完成仍必须有独立新帧确认。

当前覆盖敌方目标、全体确认、友方目标、防御、地下城恢复及恢复后返回、拆陷阱。`recovery::decide` 明确拒绝为这些结果不确定原因进行应用/实例恢复，即使配置要求强制重启或崩溃阈值为零也不例外。此前已存在的住宿付款不确定原因也不再进入重启策略。

这不是 exactly-once 声明，也不把“未确认”解释成“没有执行”。原生输入与后置事件保留供调查；没有可证明的业务回执时停止，不能自动重放。
