# WVD Next 真实启动链事故报告（2026-09-22）

## 结论

WVD Next 当前不具备可交付的真实任务执行能力，必须停止宣称“可运行现有任务”或“能够真实操作游戏”。

本次在真实 MuMu 环境点击“开始任务”后，最小链路

`连接设备 -> 检查/开启 VPN -> 启动游戏 -> 处理启动页 -> 进入游戏 -> 执行任务`

未能完成。验证期间恢复策略还在缺少充分故障证据时升级到了模拟器重启，造成模拟器被反复重启。WVD Next 服务已停止，后续不得在完成离线生产入口验证和限制恢复升级之前继续实机试跑。

## 用户可见故障

1. 点击“开始任务”后界面保持 `Idle`，错误提示只显示在长页面顶部，看起来像按钮没有反应。
2. 游戏关闭时，程序不能稳定完成 VPN 检查、游戏启动和启动页处理。
3. 启动页识别失败会被当成恢复故障，随后升级到 ADB 重连、游戏重启乃至模拟器重启。
4. 多次底层、离线和合成验证通过，但没有证明真实生产入口可用。

## 为什么此前大量验证没有发现

此前验证主要覆盖以下隔离对象：

- 生命周期权限、代次、停止和重试契约；
- 假设备中的 VPN 已就绪/未就绪状态；
- 合成画面的模板识别、输入门禁和业务状态；
- 资源哈希、Bundle 封存、构建和 HTTP 接口；
- 单个任务图或有限业务段的离线执行。

这些验证没有覆盖生产最小链：

- 没有通过真实 `Application::start_task` 装配完整多段任务；
- 没有验证生产发布物同时包含任务入口和 `Boot_Entry`；
- 没有在真实 ADB 上验证“命令非零但设备正常”的状态探测；
- 没有覆盖真实 Android 窗口切换的短暂空焦点；
- 没有覆盖系统区域设置导致的繁中首次免责声明；
- 没有把“VPN/游戏四种初始组合”作为交付门禁；
- 没有限制未知画面触发模拟器重启。

因此，旧结果至多证明部分组件契约成立，不能证明程序可用。把这些结果表述成阶段性可交付，是验收口径错误。

## 当前安全状态

- WVD Next 服务已停止，不再监听本地端口。
- 当前没有 WVD Next 任务继续操作模拟器。
- 本次候选改动未提交、未推送，不得当作已修复版本。
- 旧版 Python 程序、用户配置、mod 和日志未作为本次清理对象。

## 继续开发前的强制门禁

### 1. 生产入口离线装配测试

测试必须直接经过与生产相同的任务启动装配函数，而不是手工构造一个更理想的 `RunDefinition`。至少断言：

- 多段任务只有首段可包含初始 `EnsureVpn`；
- 所有续段均无生命周期计划；
- 发布 Bundle 中真实存在任务入口、`Boot_Entry` 和它们引用的全部资源；
- 最大实际任务加入恢复图后仍满足明确、审查过的节点预算；
- 新版专属资源进入 Manifest，哈希和来源可追踪；
- 点击启动失败时，错误显示在运行区域，而不是藏在页面顶部。

### 2. 恢复升级限制

- 单纯 `NoHit`、未知启动页或业务检查点缺失不得重启模拟器；
- 只有实例进程、Android 启动状态或 ADB 连接有明确故障证据时，才允许考虑实例级恢复；
- 实机 Smoke 默认禁止 `RestartInstance`，先验证 VPN 和游戏应用级恢复；
- 每次实机 Smoke 最多一次启动尝试，失败立即停机并保存证据；
- 不得通过延长预算、增加重试次数或重复跑到成功来掩盖失败。

### 3. 必须通过的真实最小矩阵

| VPN | 游戏 | 预期行为 |
| --- | --- | --- |
| 已开启 | 已运行且前台 | 跳过 VPN 操作，不停止或重启游戏，进入任务 |
| 未开启 | 已运行且前台 | 仅启动并确认 VPN，不重启游戏，进入任务 |
| 已开启 | 已关闭 | 跳过 VPN 操作，仅启动游戏并处理启动页，进入任务 |
| 未开启 | 已关闭 | 启动并确认 VPN，再启动游戏并处理启动页，进入任务 |

每组都必须证明：

- “开始任务”在界面上立即显示已接受、运行中或明确错误；
- 不发生未经条件证明的模拟器重启；
- 能处理英文及已观察到的繁中首次免责声明；
- 能到达一个明确的游戏内稳定场景；
- 能执行至少一个安全、可观察、可停止的任务步骤；
- 点击停止后在规定时间内静止。

## 完成标准

只有上述离线生产装配门禁全部通过，并且真实四组合矩阵在限定次数内全部通过，才能把新版状态改回“可真实运行”。构建成功、Mock 成功、合成图成功、单接口返回 202 或游戏进程被拉起，均不能单独作为完成证据。
