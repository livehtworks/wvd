# 诅咒之轮矿石跳跃故障

## 现场结论

- 本次正式作者流程停在 `wheel-select-target/Scroll1@await`，直到总时限触发 `FLOW_TOTAL_DEADLINE`；没有走到选矿石或提交跳跃。运行前半段曾固定点击左箭头十次，随后连续滚动。这不是“矿石素材缺失”。
- 运行结束后的 900x1600 现场帧中，`Time Leap` 下方为“豪雪地帶”，底部可见“美麗礦石的真相”。同一候选的只读语义探针对 `wheel.chapter.dhi`、`wheel.target.ore` 返回 `Hit`，另外三个章节标题返回 `NoHit`。这只能证明静态帧可识别，不能倒推等待节点当时捕获的每一帧。
- 本次停在章节与目标选择子流程，因此下游 `wheel-jump` 没有获得执行机会；未观察到“跳跃按钮已点击但游戏没响应”。

## 修复范围

- 原生跳轮按四章顺序识别当前标题：初始奈落、贸易水路、城塞、豪雪地带。和目标章比较后，只点一格相应方向，并以相邻章节标题确认切换；不再先盲点左侧十次。
- 公共矿石流程先查当前可见目标。当前章不是豪雪地带时，基于标题逐章向右；当前章已是豪雪地带且矿石出现时直接选择。保留其他章节目标的向左回扫路径，但从中间章节找更早章节目前可能先向右到末章再回扫，尚不是最短路线。
- 两种流程都在每次滚动后重新检测目标，不再无条件连续滚动。公共流程的参数绑定和本地已保存定义已同步；同步前备份在 `next/.local/scorpion-20260925-wheel-select-before.json`。
