# M4 业务确认与宝箱有限段

## 生产调用链

`Maa Pipeline -> WvdConfirm -> Context.capture/recognize -> WvdRunState.confirm_event -> EventJournal -> RunStore`。
确认动作与普通输入分开，不能以 SDK 返回成功直接增加计数。

- 确认取新帧，校验三态、可用性、代次和帧来源，再在业务状态锁中修改。
- 操作 ID 包含运行身份、有限段索引和编译操作名；恢复代次不进入幂等 ID。同 ID 重放不重复效果，变更效果报冲突；错误任务步或旧代次拒绝。
- 子流程内联给操作 ID 加命名空间，避免两个不同子流程被错误去重。每 Run 至多保留 4096 个确认签名，达到上限明确失败，不丢弃旧签名后重复执行。
- 业务摘要只记录确认数及最后一项摘要，完整运行仍写入既有有界事件/终态存储。没有新数据库或旧配置写入。
- 有业务确认的编译图自动包含声明的根 BusinessCheckpoint；子节点不能代替根检查点完成。

## 宝箱调用

`chest/open_chest` 在宝箱上下文中选择开箱者，优先配置角色；其他候选用封存随机种子排列。
每个角色用独立恐惧 ROI 检查，全部恐惧时拒绝动作。每次拆陷阱输入前重新识别上下文，
战斗、复活或伏击优先结束宝箱段；仅确认返回地下城后通过 `dungeon_resumed` 结算开箱。
本有限尝试的拆陷阱预算为普通 8 次、快速 30 次；更多尝试与外层分派仍待完整任务引擎承接，
不能将该有限段说成旧 StateChest 全部逻辑已经迁完。原对照为旧 `StateChest` 2996～3107。
