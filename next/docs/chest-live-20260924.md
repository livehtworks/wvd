# 繁中宝箱实机记录（2026-09-24）

## 现场与结论

- MuMu 实例 2，`127.0.0.1:16448`，900x1600。验证只使用隔离数据目录和候选服务；未修改用户 `config.json`。
- 原英文 `chestFlag` 在繁中“打開”现场帧最高 0.4411。新增“打開”和“要讓誰開啟？”的局部模板后，实机流程走过打开、选人、拆锁。
- 一次宝箱连续出现三页不同道具奖励。流程不识别道具名或图像，只识别右下角继续箭头。该箭头在三页奖励截图中匹配分数为 1.0、0.999、0.998；在初始页、选人页和开箱动画中分别低于 0.38、0.38、0.43。底部 `AUTO` 在开箱动画中也有 0.976 的误命中风险，因此没有采用。
- 从第三页奖励实机运行候选流程，发出一次右下角继续输入。游戏随后先回迷宫，再在自动导航途中进入战斗；这不是“奖励直接触发宝箱怪”。由于截图可跳过迷宫过渡帧，开箱后置分支允许直接观察到战斗或伏击，不把过渡帧设为必经条件。
- 现场繁中战斗帧原 `combat_active` 为 `NoHit`。新增左上 `ACTIVE` 局部模板后，正式 `WvdVision` 探针在该帧命中 `[31,17,91,31]`，奖励页和开箱动画为 `NoHit`。奖励箭头经正式 `WvdVision` 探针验证：奖励帧 `Hit`，动画和战斗帧 `NoHit`。

## 实现边界

- 宝箱入口接受“打开后直接奖励 / 开锁页 / 回迷宫 / 战斗或伏击”，不强制出现开锁条或奖励页。
- 奖励页可连续多页，逐页点击继续；返回迷宫或出现下一个宝箱后停止当前宝箱子流程。已识别战斗/伏击交还外层迷宫调度，未知覆盖层仍停止而不盲点。
- 迷宫父流程增加奖励页入口，支持从该页恢复；这不等于已证明所有任务的完整运行。
