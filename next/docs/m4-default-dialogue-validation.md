# M4 默认对话处理

## 来源与职责

冻结旧源码 `utils.py::reflectImage` 只列出基础 `dialogueChoices/*.png` 并按文件名排序；
`script.py::IdentifyState` 按此顺序点击首个命中选项、等待两秒后重新识别。
本次承接全部十四个基础选项，名称包含原有 `!`、`#` 前缀，不从显示文字猜名称。
旧资源加载顺序仍由统一 AssetResolver 负责，不在对话模块扫描用户目录。

- `vision/dialogue_probes.hpp`：默认候选及正常场景反证，供视觉和发布清单共同使用。
- `vision/recognizers.cpp::default_dialogue`：仅处理当前帧的识别顺序，无输入、无状态写入。
- `recovery/dialogue.cpp`：有限 Maa 子图，经 GuardedAction/InputGate 点击；不私持设备句柄。
- `recovery/boot.cpp`：普通阻塞页与启动恢复入口接入，结果不明拒绝生命周期重放。

点击前的新帧必须仍为同一优先选项，正常地图、战斗、城镇、角色面板或更高优先提示
出现时不能沿用旧坐标。点击后确认离开旧选项才结束子流程；连续不同选项由外层重新观察。
同一选项仍在时记录 `dialogue.choice_outcome_unconfirmed`，不重复购买或选择；未知后置保留
门禁失败，不把输入返回成功当业务成功。当前一次普通阻塞处理最多六次对话子调用。

旧代码用于“购买骨头/尸油”的日志分支比较无前缀名称，与实际资源名不一致；本次不据此
新增购买次数或收入。任务专用选项、强制停点与回调不属于默认列表，仍需专项逐项承接。

## 验收与当前状态

已写五个流程测试方法、二十二个因果场景：

- 十四个旧选项分别选择后返回旅店，预期各一次输入。
- 同页选项顺序及连续两个不同选项，预期两次输入。
- 旅店、角色、恢复面板上的同名图案不能触发默认对话，预期零输入。
- 点击后同页或未知页，不重放、不调用恢复端口。
- 第一次点击时停止或底层拒绝，预期最多一次输入。

预期候选名由测试只读查询冻结 Git 资源生成，不从生产 C++ 常量反推。画面只按明确
输入转换，截图不推动剧情。所有材料写入唯一 `.local` 测试目录；无实机或用户配置操作。
构建、原生结果、同产物共用链回归通过前，本项仍为待验证，不增加完整任务通过数。

### 首轮失败与定点修正

`m4-default-dialogue.log`，私有根 `m4-workflow-r016nzuu`：五方法333.572秒，18个断言失败。
十四选项、连续页及输入失败/停止预期均未实际到达输入，主要错误为 `SCENE_UNCONFIRMED`；
正常场景反证方法通过。首个选项的新帧在场景识别完成时已2839.441ms，目标完成2932.113ms，
超过2000ms TTL。因此不能把输入拒绝算对话通过，也不能降低后置要求或增加TTL。

修正一：无候选选项时直接返回NoHit；有候选后，同帧全部正常界面/高优先提示仍须排除。
借用既有OpenCV同步分片，至多四路独占模板索引/memo，合流后按原顺序消费结果与异常。
默认对话不参与外层二路并行白名单，避免嵌套扩张。普通all/any仍全量消费结果并传播错误。
不改模板、阈值、ROI、动作等待和帧身份。新产物尚待复验，首轮原始证据保留。
