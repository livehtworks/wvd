# M4 要塞八层陷阱专项

## 业务边界

固定旧 `fortress-B8F_trap` case 是不回城循环：每轮开始累计时间并增加 `_COUNTERDUNG`，按七个 TargetInfo 执行 StateDungeon，遇停止退出。它没有 `_EOT`，不能拿同名普通 dungeon 的入本或回城配置代替。

`tasks/fortress_trap` 编译一个完整有限迭代，入口只接受本内稳定场景，普通阻塞交回共用子流程。`WvdTaskPlan::with_route` 保存局部 TargetInfo，不改写目录原树。开始次数和完成次数分开，恢复同一迭代不重复开始计数；七点未完成不能走成功出口。后续重复迭代仍需 Run 的正常续段，不借重启实现循环。

标记自动移动停止后的地图确认缺项在本次依赖修正中承接，见 `m4-auto-map-validation.md`。所有按键和滑动继续经过实际 Maa、GuardedAction 和 InputGate。

## 验证状态

首次构建通过，状态组 19 方法通过（`m4-trap-state.log`）；实际流程待自动移动后置 TTL 问题修正后验证，见地图专题首轮失败记录。Python 用只读 AST 提取固定旧源码的七个常量，不 import/执行旧业务；依动作切换场景，包括每个任务点的滑动、选择、AutoMove、移动停止与重新开图，截图不推进。

待验证：完整迭代、冷启动后原任务、首动作停止/拒绝、状态层开始/完成分离与重放、正常两轮、中途已过三点后冻结/重启和提前回城负例。完整场景不把只识别七个已完成图标算作走完路线。

首次完整流程使用 `33561a3` 对应产物，5 方法中提前回城与停止/拒绝两个方法通过，完整路线/中途恢复/正常续段三个方法失败（337.803 秒）；`m4-trap-workflow.log` / `m4-workflow-s1lrdgdt` 保留证据。完整路线在第五次输入严格拒绝后失败，不是帧龄错误：实际第五次是再次开图后的拖动，夹具却预期下一任务点的 Back。固定旧源 `StateMap_FindSwipeClick` 每次重入先拖动再判断完成，因此修正夹具补齐六次再次拖动，单轮从漏项的 27 次改为 33 次；中途冻结点仍为三个已完成任务点之后的下一次 AutoMove，按独立预期动作序列定位。不修改生产地图语义、不放宽输入比对。

生命周期恢复需重新进入旧 StateDungeon 调用边界，因此入本/任务点回执加入该恢复请求的路线序号，重新开始局部路线。不能按 generation 重置所有回执：住宿、善恶写回和专项开始次数仍保持原来的幂等边界。普通续段仍使用独立 unit_index。这项改变尚待对应实测，不能以已有冷启动通过推断中途恢复通过。

M4 全任务组合及最终回归未齐，不能将该专项登记为全部通过。没有真实设备操作。
