# M4 原生子流程组合

## 目标与机制

完整路线会重复调用战斗/开箱等有限业务。复制整份角色图会使节点数随回合和任务点相乘；本阶段使用既有 `RunChild -> Context::run_child -> MaaContextRunTask`，没有新增节点调度器或 Controller。

编译器定义子图一次，在明确节点调用。静态验证区分根与子作用域，禁止调用递归、未知入口、跨作用域 next、子图到根终点和超深调用；节点及 Session 预算继续有效。内联含子调用的图时，同时命名空间化子入口及预算清单。子任务的 SDK 成功仍不能当作根业务完成。

## 首轮失败及修正

首轮 `m4-native-child-tests.log`（`next/.local/m4-workflow-nth8ysmp/`）3 方法中 2 个失败，原始证据保留：

- **命中计数共享**：每个住宿节点 max_hit=1，首轮五次输入完成，第二次子调用没有发出新输入。Maa 5.13.0 的 Context 共享命中次数，不能假定 RunTask 自动隔离。修正使用固定 C ABI 的 `MaaContextClearHitCount`，仅清除编译器封存的被调用作用域；重置清单必须与静态作用域完全一致，不能清理调用者预算。没有重置策略、帧、许可或外层回合次数，没有 Clone 新上下文。
- **输入失败被恢复出口覆盖**：子动作普通 false 允许 SDK 继续走 on_error，导致真正的底层输入失败变成 Interrupted/RecoveryRequired。GuardedAction 在非取消情况下将该失败作为异常保留；不改变通用子动作 false 必须读取 TaskDetail 的契约，停止仍按取消返回。

修后 `m4-native-child-scoped-tests.log` 为 3 方法/9 场景通过（30.531 秒），证据 `next/.local/m4-workflow-2aritncl/`。包含同一住宿子图三次执行和两级嵌套，每种都完成 15 次因果输入；输入拒绝/停止后没有后续调用；非法入口、递归、覆盖参数、跨边界和清理父预算均在输入前拒绝。

检查还补充了共享子图的最长调用深度计算，避免浅层先验证后的缓存绕过深层上限。该追加负例及受影响范围回归以本阶段后续日志为准，不改写上述首轮计数。

共享局部预算修正后的完整 M4 组为 **91 方法通过**（985.285 秒），日志 `m4-native-child-full-regression.log`。工作流证据位于 `next/.local/m4-workflow-nvb0etqm/`，其中 16 回合上限的重复角色防御场景编译为 91 节点，实际三个角色动作、三次输入后完成战斗，策略已消费、战斗计数为 1。此整组构建早于最后追加的共享深度负例，后续补验单列。

最终构建 `m4-native-child-final-build.log` 无编译警告/错误。新增深度负例、原有编译负例及子任务/遭遇组合的 **11 方法通过**（124.889 秒），日志 `m4-native-child-final-tests.log`，证据在 `next/.local/m4-workflow-vxhcj8tu/`；共享深度、父预算清理等均在连接/输入前拒绝。实现叠加表由 `m4_inventory.py --encounter-evidence` 校验当前 EXE 身份、实际输入数、终态及策略消费后更新，完整任务分母不变。

同构建 M2 100 方法通过（115.565 秒），计划 4 方法通过。追加状态回归曾与 M3 组重叠，`m4-state-tests-lufbshbw` 中出现 `start_error=DEVICE_BUSY`，两个方法因缺少成功快照报错；这是测试调度违反共享离线设备租约造成的，保留 `m4-native-child-state-regression.log`，以停止重叠后的串行补验为准，不关闭互斥或隐藏原轮结果。

M3 ROI/Custom/组合条件 3 方法通过；串行状态补验 `m4-native-child-state-serial-regression.log` 的 10 方法通过（3.515 秒）。450 个保护文件再次核对未变。本阶段没有重新运行已阻断的 M3 发现组或 M0 内存组。

## 范围

`combat/encounter.cpp` 改为共享单角色图和有限调用链，每次返回后先观察地下城/宝箱/复活，再决定是否调用下一角色。策略消费仍由 WVD 状态持有，不能因节点计数重置而恢复已用技能。

这只是完整任务组合所需的一项实现，不代表 58 项完整任务已接线。真实设备不开放，M3 的既有阻断和资源未决结论保持。

继续接完整路线前还需补“Auto 已开启但战斗尚未推进”的外层等待断言：不能把无需输入的 Auto 就绪重复算作角色行动、快速耗尽回合预算。当前证据覆盖 Auto 确认和已结束战斗撤销输入，尚不覆盖持续 Auto 推进。
