# M4 有限业务流程验证

当前仍是 M4 离线实现，不是生产切换或 58 项完整任务验收。

## 实际调用链

`navigation/world_map`、`supply/inn`、`combat/auto_combat` 构建有限图，交给
`tasks/pipeline_compiler` 校验，再由 `tasks/workflow_session` 发布不可覆盖的新资源包。
发布验证图、资源清单、别名与注册表；源 BundleLease 在复制期间持有封存。
权限由编译图提取并进入资源修订；空图、未知节点/识别器、Shell、无根终点、无界节点、
失效资源索引和已存在目的目录在发布前拒绝。
执行仍由 Maa Pipeline 推进，每次输入通过 GuardedAction 和 InputGate。
游戏模块没有新增逐节点解释器、Python 执行器或真实设备入口。

## 语义边界

- 入城段只承接“世界地图已打开且目标可见”到 Inn 确认；尚不承接外层开地图、缩放、拖动查找。
- 五个旧候选偏移逐个重新识别，最多五轮；Inn 出现后不再发送剩余地图点。
- 住宿段承接进旅店、Stay、床位、OK、返回城市；王室不可用时回经济床位。
  不把队伍选择当作住宿，不把仅出现 Stay 而 OK 仍在视为完成确认。
  旧代码中 `[299,1464]` 的住宿后对话动作尚未承接，不能据此称整条补给链完成。
- Auto 段先处理 Close、Cancel 或返回键，再确认 Auto 已开启；覆盖层最多关闭三次。
  三次未知识别后的固定点保底仍保留，但点击后必须有开启证据，不能直接宣告完成。
  不消费技能，不声称整场战斗完成。
- 补给决策区分间隔、六小时队伍刷新与镐子耗尽；强制补镐子不受普通间隔阻止。
  该决策尚未连接全任务调度，完整补给验收仍未闭合。

## 验证方法与当前证据

`tests/native/test_m4_workflow.cpp` 运行生产编译器输出的真实 Maa 图。
离线后端仅在收到独立预期的坐标/按键后换帧；被动截图保持现场，错误或多余输入失败。
每次记录 EXE hash 和实际加载 Maa/OpenCV 模块 hash。合成画面不用于证明真实识别质量。

本轮私有证据根：`next/.local/m4-business-038717bea778422ba001a95ffec4e8c6/`。

1. 测试错误地期待 Failed；核心既有契约对无恢复策略的 RecoveryRequired 返回 Interrupted。
2. 测试驱动覆盖为 15 秒，先于完整候选预算耗尽而触发 SESSION_TIME_LIMIT/STOP_TIMEOUT。
   修正为使用发布 Session 原有的 60 秒限时和 3 秒停止预算，不调整识别阈值、frame age 或生产停止契约。

无参数契约，不修改恢复与正常续段的终态语义。
组合识别同时保留子项的 action_eligible 限制：低置信 NEXT 不能因包入 all/any/not
