# M4 自动战斗持续等待

## 行为与边界

`combat/encounter.cpp` 在单角色子流程返回后重新识别：先检查地下城、宝箱和复活，再判断全自动策略且 Auto 已开启。开启状态进入独立、有限的 Maa 等待节点，不反复调用角色子流程，也不消耗下一回合预算。

等待时每轮重新观察，未识别到按钮不是发送点击的许可。只有明确识别到 Auto 关闭，才允许下一次角色判断；结束战斗则离开等待并按已有确认事件结算。独立节点预算耗尽返回 `combat.auto_progress_timeout`，不把没有进展误报为任务完成。Session 总预算和停止门禁继续有效，未增加线程、Controller 或另一套执行器。

默认最多 128 次等待节点，节点间隔 250ms；可明确编译为 1～256 次。该值是轮次上限，不是精确的 32 秒承诺，识别时间和 SDK 调度同样消耗 Session 时间。回合预算仍单独为 1～16 次。

## 验证

使用正式编译器、真实 Maa 5.13.0、WVD 识别与输入门禁。离线设备仅按期望输入及显式单调时钟事件改变图像，不按截图次数前进。

首组 `m4-auto-wait-tests.log`：4 方法、5 场景通过，35.766 秒；证据 `next/.local/m4-workflow-zlomt8p8/`。

- 开启后 4 秒才按时钟进入地下城，只有一次输入，即使回合预算为 1 也正常等待并结算一场。
- 初始开启和本次开启两种持续无进展场景，都返回专用超时，输入分别为零和一次，战斗计数不增加。
- 通过真实 SDK 的 `Node.Action.Starting` 事件确认已进入 `Turn0Poll` 后停止，结果为 `UserStopped`，无迟到输入或战斗结算。
- 点击 Auto 后直接结束战斗时，不再补一次开关输入。

补验 `m4-auto-wait-regression.log` 的 20 方法全部通过（242.319 秒），证据 `next/.local/m4-workflow-6zewdxew/`。包含时钟关闭 Auto 后重新判断并执行下一次确认输入、输入拒绝返回 Failed 且不结算，以及既有 Auto、自动寻路、遭遇与重复计数回归。450 个生产保护文件核对未变。

构建日志为 `m4-auto-wait-fixture-build.log`，每个场景 `execution.json` 保存执行前后核对过的 EXE hash，输出记录实际加载的 SDK DLL 路径/hash。此处只报告上述定点复测，不把上一阶段完整 M4/M2 结果写作这次全量复验。
