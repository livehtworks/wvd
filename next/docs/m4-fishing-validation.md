# M4 钓鱼接续验证

固定旧源 `6585f407` 的 fishing/fishing2 共用case；本阶段仅离线实现，未开放设备。
当前为待构建验证，不能写成两项完整任务通过。

## 分层与语义

- `tasks/fishing` 编译抛竿、收获页和一次有限钓鱼图；Maa拥有执行与等待。
- `vision` 负责同ROI的0/8鱼饵分数比较、尺寸/鱼类分类，以及固定水域浮标检测。
  抛竿前不是单看nobait模板；先超过原阈值，再严格大于8bait的分数。
- `fishing::Progress`由WvdRunState持有，保存待关闭收获、分类、完成次数、
  抛竿计时和超时失败数；不保存截图、坐标或SDK句柄。
- 右扫五次、左扫两次均100ms，近端抛竿4000ms、远端2250ms。
  每次重新校验页面、停止及门禁；保持地图默认400ms，不统一修改所有滑动。
- 正式单轮图在抛竿后记录等待起点，再等待10秒。等待浮标每次1秒，消失则100ms拉杆，
  后等3秒；严格超过300秒才允许超时收竿，确认离开striking后登记失败。
  两组等待节点交替，保持既有每节点256次上限，不在256秒提前报超时。
- 旧Farm先裁剪 `[250,500,400,600]` 再检测浮标；新专用模式同样裁剪，
  返回存在性，局部坐标不被当成全屏输入位置。保留原M3独立bobber模式契约。
- 鱼类只在 `[0,1100,900,150]` 查找，尺寸仍全屏。各自取最高分且严格大于0.9；
  未知鱼类记录“未收录”，未知尺寸仍计总鱼数但不伪造分类。
- 新帧分类产生待确认回执，关闭页后新帧确认才计数。相同回执幂等，停止、关闭失败
  和恢复保留未确认状态；不能从历史文件自动复发物品操作。
- 抛竿前另记待确认意图，咬钩页确认后才重置计时；重复抛竿不会沿用上一竿的超时。
  收获/抛竿未确认时应用恢复策略不重启来重放，缺饵也不是重启理由。
