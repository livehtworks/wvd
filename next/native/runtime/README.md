# 原生运行层

`NativeRunCoordinator` 持有请求、运行线程、设备租约、停止顺序与终态落盘。
`NativeExecutionSession` 为每个有限业务单元装配一次 `FlowExecutor`；后者唯一持有调用栈、事件作用域、输入回执和计时。设备输入仅通过 `InputGate` 与同一 `DeviceSession` 发出。

本层只认识中立的 `FlowProgram`、观察结果和操作端口，不判断 WVD 的技能、地图或宝箱。页面结果与业务确认分别保存；已发输入在结果不明时不能重发。恢复计划可声明停止可中断的延迟，只有设备生命周期端口能够执行关闭或启动，且不得因普通 NoHit 自动重启。

停止先关闭新输入准入，随后取消等待与可取消 I/O；清理未完成时保留 `quiescent=false` 和租约，不伪报停止完成。

程序图由 `shared_ptr<const FlowProgram>` 封存，共享的是定义而非运行状态；每次 Session/Call 都新建命中计数、回执和阶段期限。schema 4 的 Definition 累计预算来自工厂或作者声明，每次调用只签发一次；事件按暂停区间并集延长父有效预算，不延长 Run 墙钟。未声明的定义继承现有会话上限，不凭空补短超时。

PipelineCompiler 的无预算参数构造只提供原默认节点等待上限，不声明累计预算；显式预算参数和作者 execution.time_limit_ms 才进入 declared_budget。战斗/自动导航的默认60秒不能被转换成整场战斗或整段移动的累计截止。

`ObservationCycle` 仅持有当前帧及相同有效作用域已检查完的覆盖层 NoHit。输入提交、等待后轮询、事件返回和门禁身份/TTL失效均撤销周期；长纯控制链仍按现有轮询节奏重新检查事件。WVD 准备技能索引是纯业务 guard，只有游戏绑定读取标量；输入仍必须重新通过场景、目标和一次性门禁。

多分支选中的 Input 在提交前若场景/按钮/guard 已因转场消失，可退回原选择点重新观察，保留原期限并退还未执行的 hit。此来源由调用 Frame 持有；提交后、错误路由和事件 replan 即清除。pending 包含送达未知，因此绝不能重新选择或重发已提交动作。

结果明细生成之前先关闭并回收输入。富诊断分配失败时保留无分配的未决事实、`details_complete=false`，禁止宣告 Completed 或自动恢复。最外层工作线程异常只兜底清理并报告 WORKER_ABORT；正常落盘失败仍走原 storage_error 路径。

性能记账为会话内固定数组，主线程嵌套区间扣除子段；并行 worker 时间另列，不与墙钟相加。已确认技能保存起止步骤、分类耗时、真实匹配/叶缓存/ADB计数和未归因余量，未将历史缓存中的 timing_ms 当作新计算耗时。

`Call` 保存父定义帧与来源，子定义普通业务失败返回父失败边，致命故障不伪装成普通返回；`Return` 携带成功/失败结果和原因，不发设备输入。`BusinessConfirm` 由游戏层绑定并在正面证据出现后更新业务状态，不能靠流程 ID 或页面到达反推完成。`RegisteredOperation` 只能通过本会话输入门禁提交；回执先记录尝试和接受/拒绝/底层调用结果，结果未知时保留未决状态。运行线程是唯一状态推进者，HTTP 和 Vue 只读取 Coordinator 的快照；取消阻止后续提交，无法证明底层操作结果时不自动重试。
