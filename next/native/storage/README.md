# 存储层（M2 / M4）

不建数据库，不读取或写入用户 config/mod。M2 的 `RunStore` 新建运行快照并原子提交结果；
`EventJournal` 记录有界事件并保留终态提交槽，运行状态决策权仍属于 runtime。
数据属性、读写所有者、隔离目录和失败文件边界见 `../../docs/data-authority.md`。
配置 revision、旧配置导入和长期保留策略不在当前实现中，属于后续对应阶段。
导入须保持未知键、任务覆盖顺序、SKIP 字段的原存储语义，不能让 GUI 成为第二写入权威。
新增持久化类型时须同步更新数据事实文档，验收继续使用独立测试目录。

`WorkflowRepository` 的可执行文档仍只有 `<id>.json` 一份。`.builtin/<id>.json` 仅记录内置来源、接受版本和本地 revision；启动只读比较，不覆盖旧数据。显式同步检查 CAS 与固定版本引用，并在同一仓库锁下保留旧文档备份。无历史来源证据的旧文档一律显示冲突，不按同 ID 推断未修改。

RunStore 独占最近帧保存线程：一个 pending 槽、一个 in-flight，复用不可变共享 BGR，生产者 try-lock 到期提交后立即返回。JPEG 编码、目录枚举和已有滚动保留策略只在此线程执行；满槽跳过辅助历史帧并计数，错误不改变输入结果。终态前关闭接收并 join，析构兜底；join 不持诊断锁。业务回执、事件、终态和必要故障 PNG 不进入可丢弃槽。摘要区分已提交、保存失败/丢帧以及 worker 耗时。

新运行的 result.json 显式保存 details_complete。旧结果没有该字段时只读显示未知，不重写历史或当作诊断完整。
